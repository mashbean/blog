Identity matters most when systems gate action.

數位身分在 DCI 裡最重要的地方，發生在系統開始要求資格、唯一性、責任與程序正當性的時候。

如果把 DCI 看成一套讓公民得以連結、理解並行動的制度堆疊，那麼數位身分最敏感的位置，會出現在系統開始 gate action 的瞬間。 Connect 層主要處理持續性、社群治理、角色分工。Learn 層許多資訊取得不需要強身分。真正的政治壓力落在 Act。只要系統開始問你有沒有資格、是不是重複、是否屬於某個地域、年齡是否達標，數位身分就進入 public decision 的核心。 三個工作命題： 1. 主流數位身分體系在服務交付、認證、簽章、合規上已相當成功 2. 當身分基礎設施進入年齡驗證、平台治理與公共空間入口，它開始決定誰能進入 3. wallet、selective disclosure、ZK 的成熟，讓較民主的設計第一次進入可行區

我建議把數位身分先拆成兩層。第一層是發證正當性（Issuance Legitimacy），處理法律效力、主權、制度問責。第二層是交換架構（Exchange Architecture），處理憑證如何持有、出示、驗證、撤銷、跨系統重用。 我想加一個詞叫 civic proof，把焦點從「證件本身」移到「能不能支撐公共行動的證明形式」。 四個條件：匿名、不可連結、可驗證、可問責。這四個條件必須同時成立。違反直覺但自洽的是：可問責並不需要以實名為前提。

需求型態典型場景上層需要什麼正當性下層需要什麼交換架構對自由與隱私的最低要求

國家賦予的根身分仍是主流，真正分化的地方在下層交換架構與生態治理。

從上層看，高保證力的信任根仍然多半由國家提供。個人自發行身分（如 ethereum address）、公民團體、企業發行的身分，基本上都無法滿足 legal proof 和 attribute proof 需求。 真正開始分化的是下層交換架構。這十年來，COVID-19 是轉折點，因為疫苗護照的敏感個資，不同標準組織提出「去中心身分」概念。 世界各地的競爭焦點，已經從「誰發身分」擴大成「誰控制信任清單、誰控制呈現介面、誰承擔 verifier onboarding 與 ecosystem cost」。

MOICA = Ministry of the Interior Certification Authority · moica.nat.gov.tw · TW DIW GitHub
台灣值得單獨講，因為它同時包含 warning case 與 testbed。 MOICA 是 PKI 晶片卡，高保證力、強法效。但問題在於開放生態的接入摩擦高度 issuer-centric。2020 年 New e-ID 因民眾反彈暫緩。 TW DIW 走另一條路，把既有憑證轉成可由持有者管理的數位憑證卡片。強調選擇性揭露、互通、開放生態、多發證者。但 civic burden 的重新分配是關鍵問題——多信任根把理解、授權、驗證、申訴門檻轉嫁給民眾。 台灣最值得觀察的，不在哪一套技術先進，而是兩種不同治理負擔分配方式放在同一個政策現場。

Taiwan Civic Cases

Case A: PTT × MOICA × ZK 藍勾勾

台灣最大 BBS 系統 PTT，以自然人憑證產生 ZK proof，讓使用者在不揭露真實身分下拿到「藍勾勾」，降低選舉期間網軍攻擊。

證明：國家根憑證 → trust root，但不必把 full identity 交給平台。

g0v Summit 2026，台灣最大公民科技社群年會，使用數位皮夾發放入場憑證，由非政府第三方擔任 issuer 與 verifier。

證明：holder-centric 生態不只能由政府操作，公民社群也可運作。

案例 A：PTT 工程團隊以自然人憑證產生 ZK proof，讓使用者拿到藍勾勾。等於示範了國家根憑證可以提供 trust root，但不必讓平台知道具體是誰。 案例 B：g0v Summit 2026 志工團隊將使用數位皮夾發放證件與入場憑證，非政府第三方擔任 issuer 與 verifier。直接證明 holder-centric 生態不是只能由政府操作。 兩者形成對照：前者拿強國家 credential 產生低揭露 proof，後者用 wallet 架構擴大非政府發證與驗證的實作空間。

當主流制度未充分支援低暴露、可攜、可驗證的 civic proof，公民與次國家實驗就會出現。 Vocdoni 在 2017 年加泰隆尼亞獨立公投失敗後出現，透過西班牙護照驗證持有者進行模擬投票。Rarimo 在羅馬尼亞、俄羅斯與伊朗有小規模模擬投票。QuarkID 顯示城市級政府也在嘗試 citizen-controlled credentials。 但我採取節制說法：這些是需求證據，不是替代證據。它們大多仍依賴既有護照、會員邊界等制度型 trust root。 更深的政治問題：如何讓公民相信政府提供的證件不會變成追蹤工具。若公民相信 credential 只是 trust root，驗證流程不會回傳國家，接受度會完全不同。

DID = Decentralized Identifier · EBSI = European Blockchain Services Infrastructure
Public blockchain 在數位身分中有高制度想像，但真正大規模部署的國家案例目前只有不丹與台灣。 我的看法：最適合的位置是 trust layer、status anchoring、跨組織共見、可稽核的狀態發布。不是把個資上鏈。合理的上鏈內容是 issuer DID、公鑰、trust list 錨點、status list 承諾值。 為什麼強調 public blockchain：少數能同時提供 permissionless publication、跨組織共見、獨立驗證、抗單點失效的工具。 未來方向是 federated trust-list alliance：不同法域的 trust list 彼此橋接，可對接、可查核、可分層治理。我參與了一年 ICANN 相關 fellowship 理解 DNS 信任根的建立，結論是 DNS 走出了與國家權力完全不同的道路，在數位身分領域很難重現。

在我的工作經驗裡，從政府方推動 DCI 極為困難。最困難的不是技術應用，而是用公務員、民間團體可以理解的語言，將技術架構與政治哲學轉化為採購需求、milestone 檢核點。 五個可操作的動作： 1. Privacy-first baseline：最小揭露、不可連結、no-phone-home、自願性、替代路徑、申訴救濟。 2. Open wallets / standardized provisioning：presentation layer 會成為新 gatekeeper。 3. Procurement sandbox：很多權利主張進入 rollout 就消失，因為沒被翻成採購語言。 4. Testbed network：挑幾種 civic use case 做小規模試驗。 5. AI delegated authority：AI agent 已快速侵入，問題從「誰登入」轉成「誰可代表誰行動」。

Conclusion

A democratic digital identity system should determine
when I can act without exposing more than necessary.
  1. 哪些 civic acts 需要 legal identity，哪些只需要 attribute proof 或 uniqueness proof？
  2. Browser、OS、wallet 是否已成新的公共基礎設施？它們會怎麼形塑公民生活？
  3. 若 state-rooted credentials 仍為主流，什麼樣的 exchange architecture 足以支撐 privacy、portability、redress、inclusion？
  4. 這個研究應如何收斂，才不會過度發散？
  5. Practitioner、policy advocate、researcher 的下一步各是什麼？

mashbean · mashbean.net · Allen Lab Policy Fellow

最後的句子：一個民主社會需要的數位身分體系，不只要證明我是誰，也要決定我在什麼時候可以不暴露超過必要的資訊，仍然能合法參與公共生活。 從 DCI 的角度看，核心問題不是如何讓每個人更容易被辨識。更重要的是，如何把具正當性的資格來源，轉成低摩擦、低暴露、可救濟的 civic proof。 我最大的困擾：1. 研究方向牽涉太多領域，應沿什麼軸收斂。2. 從行動者、倡議者、學術研究者三個位置看，下一步各自是什麼。
