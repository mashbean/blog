// 1996 · communications decency act

先回到憲法之外的「避風港」起點。

"No provider or user of an interactive computer service shall be treated as the publisher or speaker of any information provided by another information content provider."

— 47 U.S.C. § 230 (c)(1)

// 平台不為使用者內容負責

使 YouTube、Facebook、Reddit、Wikipedia、PTT 都能存在的法律前提。沒有 §230，就沒有現代 UGC 平台。

// good samaritan 條款

平台「善意」做內容審查時，不會因此被視為發布者——這保住了平台同時擁有「不審查」與「審查」的法律自由。

cypherpunk_2026.deck § 2 · platform16 / 56

// 30 years later · §230 修法壓力

三十年後，左右兩派都想動 §230。

// 從左方

  • FOSTA-SESTA（2018）
    性交易例外，第一個成功削弱 §230 的修法
  • EARN IT Act（2020–）
    兒少性剝削；強制平台掃描內容
  • KOSA Kids Online Safety Act
    2024 參議院 91:3 通過；眾議院卡關

// 從右方

  • EO 13925（2020 川普一期）
    指控平台「政治偏見」濫用 §230；拜登 2021 撤銷
  • Murthy v. Missouri（2024）
    最高法院迴避實質判決，但「政府施壓平台」議題未結
  • Moody v. NetChoice（2024）
    確認平台 content moderation 受第一修正案保障
// §230 沒有被推翻，但「平台必須對某些內容負責」的例外清單在加長

cypherpunk_2026.deck § 2 · platform20 / 56

// downrank / limit / shadowban

看不見的審查，
比刪文更難挑戰。

傳統審查： 內容被刪除 → 使用者收到通知 → 可以申訴 → 可以提告 → 有司法救濟路徑

演算法降權： 內容仍在 → 使用者沒收到通知 → 不知道發生了什麼 → 無法申訴 → 沒有司法路徑

// 法律難題

DSA Art. 17 規定平台必須給「statement of reasons」——

但「限流」是否觸發？
「不推薦」算不算限制？
「演算法調整」要不要說明？

這是 2026 仍未解的執法前線。

// matters · governance tooling 2019→2024

  1. 人工審查 · 2019

    所有檢舉送到後台，編輯團隊一條條看。延遲高、不可規模化。

  2. 帳號註銷 · 2020

    硬手段：直接刪帳號。但「永久」的成本太高，誤殺難以挽回。

  3. 小黑屋（可逆隔離）· 2023

    不刪除、不註銷——只是「公共面排除」。可恢復、可申訴。

  4. 模型守門 · 2024 → spam-detection-scaffold

    三層：① 語義（BERT 分類）② 行為（AWS Lambda 偵測模式）③ 信任評分。

// 核心原則：不刪除，而是公共面排除。內容仍在 IPFS，只是平台首頁不推薦。

// open source ≠ open process

開源 ≠ 共創

理論上：
所有程式碼、所有參數、所有判斷規則——全部公開。

現實上：
spam-detection 的閾值一旦公開，攻擊者就能調整輸入避開偵測。

折衷：分層開源——
程式碼公開，但敏感參數延遲發布 6–12 個月。

「sustaining 一個 censorship-resistant 平台，
很多時候要犧牲透明度來換安全。」

以人為本的數位身分

// principle 01

多元身分

身分自古以來都是模糊定義，介於法定與約定俗成之間。

數位社會中，法定身分、企業服務帳號、社會關係已高度重疊——卻仍沒有夠成熟、安全、易用的 UX。

// principle 02

數位自主 / SSI

Self-sovereign Identity——
使用者持有憑證、決定何時揭露、不可被第三方追蹤。

降低數位足跡招致監控的可能。

// Alex Preukschat & Drummond Reed · Self-Sovereign Identity · Manning, 2021
